## What It Is

OKF is Google's open specification for representing the metadata, context, and curated knowledge that AI systems need — as plain **markdown files with YAML frontmatter**, organized in a simple directory structure. It formalizes what the blog post calls "the LLM-wiki pattern" (the same pattern this repo's own `wiki/` directory implements) into a portable, vendor-neutral standard, rather than inventing a new database or storage format for the underlying data itself.

## Why It Exists

Foundation models and agents lack the context they need to produce accurate results, and most organizational knowledge lives fragmented across incompatible systems — metadata catalogs, wikis, code comments, shared drives. Every vendor has historically reinvented its own catalog, SDK, and schema, which locks knowledge behind specific platforms and creates redundant effort every time someone builds a new AI agent. OKF's goal is a format that survives moving between systems, lives in version control, and is directly readable by both humans and agents without translation.

## Core Entities

- **Knowledge Bundle** — a hierarchical collection of markdown documents; the unit of distribution.
- **Concept** — an individual unit of knowledge: one markdown file, with a YAML frontmatter block followed by a markdown body. Two filenames are reserved for structure (`index.md`, `log.md`); every other `.md` file is a concept.
- **Attested Computation** — a specialized concept type that pairs a sanctioned calculation method with the machinery to verify it.

## Design Principles

1. **Minimally opinionated** — the only required frontmatter field is `type`. Producers define their own content models beyond that; recommended fields (`title`, `description`, `resource`, `tags`) are optional conventions, not requirements.
2. **Producer/consumer independence** — a bundle can be hand-authored by a human and consumed by an agent, generated by a metadata pipeline and browsed in a visualizer, or synthesized by one LLM and queried by another. The format doesn't care which.
3. **Format, not platform** — vendor-neutral, no proprietary accounts or SDKs required, never tied to a specific cloud, database, or model provider. Value comes from adoption breadth, not ownership.
4. **Optional metadata "families"** layered on top of the one required field: **provenance** (`sources`, with credibility signals like `author`, `usage_count`, `last_modified`), **trust** (`generated` / `verified` — creation and confirmation checkpoints), and **lifecycle** (`status`: draft/stable/deprecated, `stale_after`).

## Reference Implementation

Google's repo ships a two-pass reference agent that generates OKF bundles from BigQuery datasets:

1. **BQ pass** — scans a BigQuery dataset and emits one markdown concept per table, with schema metadata in the frontmatter.
2. **Web pass** — an LLM-powered crawler enriches those docs by fetching seed URLs, deciding whether a page warrants a new concept doc or an update to an existing one.

Sample bundles (GA4, Stack Overflow, Bitcoin, Acme Retail) ship alongside a `visualize` command that renders any bundle as a self-contained, interactive HTML force-directed graph — demonstrating that consumption doesn't require any proprietary tooling, just something that can read a directory of markdown files.

## Notable Parallel

The structural resemblance to this repo's own wiki is not superficial: OKF's Knowledge Bundle → Concept hierarchy, `type`-tagged frontmatter, and reserved `index.md` convention are close to `wiki/`'s own `weeks/` / `tools/` / `builds/` / `concepts/` layout with required frontmatter. OKF is effectively an attempt to standardize that pattern so it interoperates across tools and organizations instead of staying bespoke to one repo.
