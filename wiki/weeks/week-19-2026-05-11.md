# Week 19 — May 11

## AI Learning: Agent Evaluation

Worked through agent evaluation interactively, sourced from Cameron Wolfe's deep-dive guide, LangChain's trajectories-vs-outputs framework, and the Langfuse evaluation cookbook. Built up a six-part theory of why evaluating an agent is a different problem than evaluating a single LLM completion: outcome correctness doesn't imply a safe or efficient path (trajectory vs. outcome evaluation, with three sequence-matching strictness levels and a finer per-call granularity layer); LLM-as-judge reliability comes from decomposing quality into orthogonal dimensions and using anchored graduated scales rather than one holistic pass/fail; deterministic checks and LLM judges layer like a testing pyramid, extended into production as real-time gates vs. sampled audits; synthetic eval-set generation needs human review specifically for the tail cases a generating model is blind to; and production quality degrades post-launch from input-distribution drift and silent dependency drift, neither of which shows up in a code diff.

Then used [Strands Agents](../tools/strands-agents.md)'s `evals-sdk` documentation (44 sub-pages, read in full) as a case study to check the theory against a real implementation — confirming most of it maps directly, while surfacing three genuinely new categories the general reading hadn't covered: adversarial red-teaming (closed-loop adaptive attacks), chaos/fault-injection testing (breaking the environment rather than the input), and simulation (LLM-generated personas/tool stand-ins solving the upstream problem of producing a trace to evaluate at all).

## Build

Learned Redis interactively, starting cold — installed it locally, explored `SET`/`GET`/`TTL`/`EXPIRE`/`INCR` directly in `redis-cli` to build tactile intuition for TTL sentinel values (`-2` no key, `-1` no expiry, `nil` from `GET` on a missing key) before writing any code.

Then built a rate limiter three times over, each version fixing a real flaw in the last: a naive `INCR` + conditional `EXPIRE` limiter in Python, which was then deliberately broken by simulating a crash between the two calls (leaving an orphaned counter with `TTL -1` forever); a fix using a Lua script executed atomically via `EVAL`, since Redis runs the whole script as one indivisible unit under its single-threaded model — no gap for a client-side crash to land in; and a further upgrade to a sliding-window log using a Redis sorted set (`ZADD`/`ZREMRANGEBYSCORE`/`ZCARD`) to eliminate the fixed-window's boundary-burst flaw, still wrapped in Lua for the same atomicity reason.
